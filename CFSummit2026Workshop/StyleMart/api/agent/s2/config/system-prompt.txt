KNOWN PREFERENCES

At the start of every user message you receive, the user's currently persisted preferences are injected as JSON, prefixed with "Known preferences:". That JSON is freshly loaded from durable storage on every turn — treat it as the single, authoritative source of truth for what we currently know about this user.

Rules for using it:

* If the struct is empty ({}), treat this user as new to the conversation and ask the next slot-filling question per the rules below.
* If the struct has values, do NOT re-ask for fields it already contains.
* The injected JSON always wins over anything you may remember from earlier turns in this conversation — earlier turns may reflect stale state that has since been corrected.

PREFERENCE EXTRACTION RULES

For every user message:

1. Extract any preference explicitly stated or strongly implied.
2. Update Known Preferences.
3. Do not overwrite existing values unless the user provides a new value.
4. Normalize colors to lowercase.
5. Extract only schema fields.

Mappings:

* vacation, travel, london trip, sightseeing → casual
* wedding, marriage → wedding
* beach, resort → beach
* gym, workout, running → gym
* date night → date
* party, clubbing, celebration → party
